Migration · 5.x → 6.x

Modernize without guesswork.

The familiar five methods remain. Version 6 tightens runtime support and fixes edge behavior around one-shot handlers, registry mutation, chaining, and list isolation.

  1. Move to Node 22.12 or newer

    Production package support now follows the vanilla-test v2 baseline and current native ESM runtimes.

  2. Install the new major after publication

    npm install event-pubsub@6

    Version 6 is currently verified on main; this command becomes available when the registry release is published.

  3. Keep the package import

    import EventPubSub, { EventPubSub as Named } from 'event-pubsub';

    The supported runtime paths are event-pubsub and event-pubsub/index.js. Other historical deep imports are no longer public and fail with ERR_PACKAGE_PATH_NOT_EXPORTED in Node.

  4. Review observable edge fixes

    emit remains fluent as it was in 5.x. One-shot state no longer mutates handler functions. New handlers wait for the next dispatch, while handlers removed before their turn are skipped.

  5. Treat list as a snapshot

    Each access returns a null-prototype object with copied handler arrays. Mutating or deleting values in that snapshot no longer changes the live registry. Use Object.hasOwn(snapshot, type) instead of snapshot.hasOwnProperty(...).

  6. Run your own integration suite

    Pay special attention to code that depended on undocumented handler symbols, shared list arrays, or mutation during an active dispatch.

Preserved

on, once, off, emit, reset, wildcard-first order, synchronous execution, default/named exports, and the wildcard list symbol.

Removed tooling

copyfiles, c8, and the test-only static-server dependency are gone. Tests and coverage now use vanilla-test 2.1.1 directly.
